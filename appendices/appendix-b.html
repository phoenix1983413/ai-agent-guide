模型选型速查

三维度对比 / Agent 特需能力 / 模型路由 / 国内合规

Agent 对模型的要求比普通 Chatbot 更高：函数调用稳定性、长上下文、多轮工具结果的整合能力，任何一项掉链子都会让 Agent 在第三步崩溃。以下速查表按「延迟 / 成本 / 能力」评分（1–5 星）：

模型延迟成本推理能力函数调用长上下文推荐用途
GPT-4o⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐复杂规划、多步推理
Claude 3.5 Sonnet⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐长文档、代码生成
Gemini 1.5 Pro⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐多模态、长上下文

Llama 3.1-8B⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐端侧、低延迟场景
评分随版本快速变化，本表给出的是相对量级而非绝对值。选型前请用第 9 章的评测框架对你的真实任务跑一轮对比，比任何榜单都可靠。

Agent 场景的特需能力

普通 Chatbot 的选型逻辑在 Agent 上会失效，四个 Agent 专属考察点：

  1. 函数调用可靠性：工具多（>10 个）时是否仍能选对工具、参数是否稳定符合 Schema。这是 Agent 的生死线，用你自己的工具集实测。
  2. 长上下文利用效率：标称 128K 不等于全程有效。跑「大海捞针」测试（把关键信息埋在文档中部），确认命中位置与丢失区间。
  3. 多轮工具结果的整合：连续 3 轮工具返回后，模型是否还会记得第一步的目标、忽略中间噪音。
  4. 输出格式遵从性：要求 JSON 输出时的格式合规率（用 JSON Schema 校验），决定你要写多少重试逻辑。

模型路由策略

生产级 Agent 不绑定单一模型，按任务复杂度路由，兼顾成本与能力：

  • 简单任务（分类、提取、格式转换）→ 小模型（4o-mini / 7B 级），成本低、延迟低。
  • 中等任务（单步推理、简单规划）→ 中端模型（Sonnet / V3 级），性价比最优。
  • 复杂任务（多步规划、代码生成、长文档分析）→ 旗舰模型（4o / Claude 级），能力优先。
  • 兜底策略：小模型输出校验失败（格式错 / 置信度低）时，自动升级到旗舰模型重试。

Python 版本（复杂度路由器）

"""
模型路由器 —— Python
按任务复杂度选模型；小模型结果校验失败自动升级旗舰模型。
"""
from __future__ import annotations
import json, re
from dataclasses import dataclass

@dataclass
class ModelSpec:
    name: str
    tier: int                # 1 旗舰 / 2 中端 / 3 轻量
    max_tools: int           # 可靠函数调度的工具数上限

MODELS = [
    ModelSpec("gpt-4o",           1, max_tools=50),
    ModelSpec("claude-3-5-sonnet",2, max_tools=30),
    ModelSpec("deepseek-chat",    2, max_tools=30),
    ModelSpec("gpt-4o-mini",      3, max_tools=10),
]

def classify_complexity(task: str, tool_count: int, require_json: bool) -> int:
    """轻量启发式分类；生产中可换成小模型分类器。"""
    score = 0
    if tool_count > 10:
        score += 1
    if require_json:
        score += 1
    if re.search(r"(规划|计划|多步|分析|架构|对比)", task):
        score += 1
    if len(task) > 500:
        score += 1
    return score

def route(task: str, tool_count: int = 0, require_json: bool = False) -> list[str]:
    """返回候选模型链：[首选, 兜底, 兜底...]"""
    complexity = classify_complexity(task, tool_count, require_json)
    tiers = {0: [3, 2, 1], 1: [2, 1], 2: [1]}[min(complexity, 2)]
    chain: list[str] = []
    for tier in tiers:
        for m in MODELS:
            if m.tier == tier and tool_count <= m.max_tools and m.name not in chain:
                chain.append(m.name)
    return chain

def run_with_fallback(candidates: list[str], call) -> tuple[str, str]:
    """依次尝试，校验失败升级下一档，直到旗舰模型。"""
    last_err = ""
    for model in candidates:
        out = call(model)
        if is_valid(out):
            return model, out
        last_err = f"{model} 输出未通过校验"
    raise RuntimeError(f"全部候选失败：{last_err}")

def is_valid(out: str) -> bool:
    """演示校验：非空且（若是 JSON）可解析。"""
    if not out.strip():
        return False
    try:
        json.loads(out)
        return True
    except Exception:
        return bool(re.search(r"[\u4e00-\u9fff]", out))   # 含中文视为自然语言回复

if __name__ == "__main__":
    for task, tools, js in [
        ("把这段话分类成三个主题之一", 1, True),
        ("设计一个多智能体代码评审流程", 12, False),
    ]:
        print(task[:12], "→", route(task, tools, js))

TypeScript 版本（复杂度路由器）

/**
 * 模型路由器 —— TypeScript
 */
interface ModelSpec { name: string; tier: 1 | 2 | 3; maxTools: number }

const MODELS: ModelSpec[] = [
  { name: "gpt-4o",              tier: 1, maxTools: 50 },
  { name: "claude-3-5-sonnet",   tier: 2, maxTools: 30 },
  { name: "deepseek-chat",       tier: 2, maxTools: 30 },
  { name: "gpt-4o-mini",         tier: 3, maxTools: 10 },
];

function classifyComplexity(task: string, toolCount: number, requireJson: boolean): number {
  let score = 0;
  if (toolCount > 10) score++;
  if (requireJson) score++;
  if (/(规划|计划|多步|分析|架构|对比)/.test(task)) score++;
  if (task.length > 500) score++;
  return score;
}

export function route(task: string, toolCount = 0, requireJson = false): string[] {
  const complexity = Math.min(classifyComplexity(task, toolCount, requireJson), 2);
  const tiers = { 0: [3, 2, 1], 1: [2, 1], 2: [1] }[complexity];
  const chain: string[] = [];
  for (const tier of tiers) {
    for (const m of MODELS) {
      if (m.tier === tier && toolCount <= m.maxTools && !chain.includes(m.name)) {
        chain.push(m.name);
      }
    }
  }
  return chain;
}

function isValid(out: string): boolean {
  if (!out.trim()) return false;
  try { JSON.parse(out); return true; } catch { return /[\u4e00-\u9fff]/.test(out); }
}

export async function runWithFallback(
  candidates: string[],
  call: (model: string) => Promise<string>,
): Promise<{ model: string; output: string }> {
  for (const model of candidates) {
    const out = await call(model);
    if (isValid(out)) return { model, output: out };
  }
  throw new Error("全部候选失败");
}

console.log(route("设计一个多智能体代码评审流程", 12, false));
// → [ "gpt-4o" ]

国内合规与部署提示

  • 面向国内公众提供生成式服务：需通过安全评估、做算法备案，模型应选用已备案的基础模型。
  • 数据不出域：优先国内云厂商或支持国内地域的 OpenAI 兼容端点；出海业务再考虑海外模型。
  • 成本敏感场景：DeepSeek V3 等国产模型在中文 Agent 任务上性价比突出，但需实测函数调用稳定性。
  • 私有化部署：Qwen2.5 等开源模型 + vLLM / SGLang，适合数据敏感及端侧，但需要 GPU 运维能力。

补一课：后训练如何塑造模型行为

选型时看懂「模型怎么炼成的」，比对比参数更有用。后训练分两步，它们分别塑造 Agent 的不同侧面：

阶段做什么对 Agent 的影响
SFT 监督微调用「问题 → 标准回答」示范数据训练决定格式遵循、工具调用语法、拒绝边界——Agent 靠它学会「怎么调用」
RL 强化学习用奖励信号（答案对不对、步骤是否高效）优化策略决定推理深度、稳定性、长任务不跑偏——Agent 靠它学会「怎么走对」

实用推论：① 工具调用总报语法错 → 找 SFT 强调工具格式的模型，而不是换更大的；② 单步都对但长任务跑偏 → 看 RL 阶段奖励是否含「过程效率」；③ 推理模型（o1/R1 类）把更多算力花在 RL 上，表现为「想得久」——按 5.6 节分档使用。

开源模型分级：按任务难度选尺寸

本地/开源路线选型，先按「任务难度」定档，再按「显存预算」定尺寸——顺序反了就会要么性能不够、要么浪费卡。以 Qwen2.5 系列为例（其他开源系可类比）：

任务难度典型任务推荐档位推理显存（INT4 参考）备注
L1 结构化小任务分类、抽取、改写、路由判断3B–7B3–6 GB可高并发批量，成本最低
L2 日常对话问答客服对答、文档总结7B–14B6–12 GB性价比甜点区
L3 复杂推理多步规划、代码生成32B 起或云端旗舰24 GB+本地只能上量化，质量有损
微调训练领域适配LoRA / QLoRA（见第 12 章显存账）10–30 GBQLoRA 让 3060 也能训 7B

路由是标配不是选修：生产环境的标准结构是「L1/L2 任务走本地小模型，L3 或检测到困难时升级云端旗舰」——本附录前文的复杂度路由器就是干这个的。评估一个新开源模型行不行，用第 9 章的评测框架跑你自己的 20 条 case，别看公开跑分：通用跑分高不代表在你的领域任务上好，垂直领域里 7B 专用模型打赢 100B+ 通用模型是常事。
