第 13 章

Agent 与外部系统集成

企业系统对接 / 实时数据流 / 代码执行沙箱 / API 经济

学习目标

  • 为企业系统选对对接模式：API、事件流还是数据库
  • 把代码执行关进沙箱，并设计密钥轮换
  • 识别企业级集成的五种反模式，绕开它们

章节地图：13.1 系统对接 → 13.2 实时数据流 → 13.3 代码沙箱 → 13.4 API 经济 → 13.5 五种反模式 → 本章产出。

13.1 企业系统：ERP / CRM / OA 的对接模式

Agent 要落地企业，必须接入现有系统。三种对接方式：

  • REST / GraphQL API：标准方式，适合有开放 API 的系统（Salesforce、钉钉、企业微信）。
  • 数据库直连：Agent 直接读业务库。优点是灵活，缺点是耦合重、权限难控。只适合只读查询。
  • RPA / 模拟操作：对没有 API 的老系统（如 legacy ERP），用 RPA 模拟人工操作。成本高、脆弱，作为最后手段。

13.2 实时数据流：WebSocket、事件总线、消息队列

Agent 不是只响应请求，还要感知外部变化。实时数据流架构：

  • WebSocket：适合前端 ↔ Agent 的双向通信，低延迟。
  • 事件总线（Event Bus）：Kafka / RabbitMQ，适合系统间解耦。Agent 订阅事件，触发行动。
  • 消息队列：异步任务、削峰填谷。Agent 从队列消费任务，结果回写。

13.3 代码执行沙箱：Docker / Firecracker / E2B

Agent 需要「会写代码」的能力，但直接执行用户代码是自杀。沙箱选型：

方案启动速度隔离强度成本适用场景
Docker中（秒级）中低内部工具、非敏感代码
Firecracker快（毫秒级）高（microVM）中多租户、安全敏感
E2B快高按量快速集成、不想自己运维

13.4 API 经济：按量计费、限流、密钥轮换

Agent 调用外部 API 会产生费用和风险。工程控制：

  • 按量计费：每个工具调用记录 token 数 / 调用次数，月底对账。
  • 限流：单用户 / 单任务的最大 API 调用次数，防止滥用或循环调用。
  • 密钥轮换：API key 定期自动轮换，泄露时一键吊销。

13.5 企业级集成的五种反模式

企业集成失败，很少是技术不行，多数是姿势不对。五种高频反模式，按伤害排序：

反模式表象后果正解
大爆炸接入一次对接 ERP 全部模块半年看不到产出，预算烧完从一个「高频 + 低风险 + 可度量」的场景切入
影子 IT业务团队自己拉个 Agent 直连生产库权限失控、审计真空平台提供受控通道，让合规的路成为最省事的路
把 Agent 当 ETL用 LLM 做大批量确定性转换又贵又不稳还不可回归确定性转换用代码，LLM 只做「理解与生成」
绕过主数据Agent 自建客户 / 物料档案两套数据打架，信任崩塌只读主数据，写操作走主系统的受控 API
忽视回滚上线后才想「怎么撤」一次故障演变成事故每个集成点先写回滚方案再开发

一张自查表：① 我们的集成点有几个？每个的负责人、回滚方式、审计日志在哪？② 写操作是否全部经过审批链？③ Agent 产生的数据进入主系统前有校验层吗？三问答不上来，先补治理再扩场景。

动手实验

  1. 画出你的 Agent 与所有企业系统的连接图，标注每条连接的读写方向和审批链。
  2. 对照 13.5 节五种反模式给你的项目打分（0-2），超过 5 分的项目暂停扩场景，先还技术债。
  3. 挑一个写操作，完整走一遍「回滚方案」：触发条件、回滚步骤、数据修复、通知谁。

本章产出：企业 IM + 知识库集成示例（双语言）

以下示例演示 Agent 如何接收企业 IM 消息、查询知识库、回复用户。

Python 版本

"""
企业 IM + 知识库集成示例 —— Python
依赖：fastapi, httpx（模拟 HTTP 客户端）
"""
from __future__ import annotations
import asyncio
from dataclasses import dataclass
from typing import Any

# ---- 模拟外部系统 ----
class KnowledgeBase:
    async def search(self, query: str) -> list[dict]:
        return [{"id": 1, "title": "请假流程", "content": "提交 OA 审批…"}]

class EnterpriseIM:
    async def send_message(self, user_id: str, text: str):
        print(f"[IM] -> {user_id}: {text}")

# ---- Agent 集成层 ----
class AgentIntegration:
    def __init__(self):
        self.kb = KnowledgeBase()
        self.im = EnterpriseIM()

    async def handle_message(self, user_id: str, message: str):
        # 1. 意图识别（简化）
        if "流程" in message or "怎么" in message:
            # 2. 查询知识库
            docs = await self.kb.search(message)
            # 3. 生成回复（简化）
            reply = docs[0]["content"] if docs else "暂无相关文档。"
        else:
            reply = "请咨询 HR 或查阅知识库。"
        # 4. 回复 IM
        await self.im.send_message(user_id, reply)
        return reply

# 使用示例
async def main():
    agent = AgentIntegration()
    await agent.handle_message("user_001", "请假流程是什么？")

if __name__ == "__main__":
    asyncio.run(main())

TypeScript 版本

/**
企业 IM + 知识库集成示例 —— TypeScript
*/
class KnowledgeBase {
  async search(query: string): Promise> {
    return [{ id: 1, title: "请假流程", content: "提交 OA 审批…" }];
  }
}

class EnterpriseIM {
  async sendMessage(userId: string, text: string): Promise {
    console.log(`[IM] -> ${userId}: ${text}`);
  }
}

class AgentIntegration {
  private kb = new KnowledgeBase();
  private im = new EnterpriseIM();

  async handleMessage(userId: string, message: string): Promise {
    let reply: string;
    if (message.includes("流程") || message.includes("怎么")) {
      const docs = await this.kb.search(message);
      reply = docs[0]?.content ?? "暂无相关文档。";
    } else {
      reply = "请咨询 HR 或查阅知识库。";
    }
    await this.im.sendMessage(userId, reply);
    return reply;
  }
}

// 使用示例
(async () => {
  const agent = new AgentIntegration();
  await agent.handleMessage("user_001", "请假流程是什么？");
})();
