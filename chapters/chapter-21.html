第 21 章

构建你自己的第一个 Agent 产品

MVP 三层结构 / 冷启动 / 灰度发布 / 持续运营 / 30 天路线图

21.1 从原型到 MVP：最小可用 Agent 的三层结构

MVP（Minimum Viable Product）不是「什么都做一点」，而是「只做最核心的一环，做到可靠」。Agent 产品的 MVP 三层：

  1. 感知层：一个输入通道（聊天框 / API / Webhook）。
  2. 大脑层：一个 LLM 调用 + 一个工具（如搜索或数据库查询）。
  3. 行动层：一个明确的输出（回复 / 文件 / 工单）。

验证标准：能用这个 MVP 完成 3 个真实用户任务，且成功率 > 80%。达标后再加工具、加记忆、加多 Agent。

21.2 冷启动：第一批工具和记忆怎么建

冷启动阶段没有用户数据，靠人工 bootstrap：

  • 工具：先做 3–5 个最高频的工具，每个工具都有明确的成功 / 失败标准。
  • 记忆：人工编写 20–50 条「常见问题 → 答案」对，作为初始知识库。
  • 评测集：在第一个用户进来之前，先建好 50 条 eval case，确保 baseline 质量。

21.3 灰度发布：小流量验证、回滚策略

Agent 的黑盒性质比传统软件高，灰度策略要更保守：

  • 内部灰度：先给公司内部用 1 周，收集 bad case。
  • 小流量外放：开放给 5% 真实用户，监控错误率和人工接管率。
  • 回滚：Agent 出问题不是「降级」而是「关闭」——一键切回人工或旧系统。

21.4 持续运营：反馈循环、版本迭代、用户教育

Agent 上线只是开始，持续运营才是核心竞争力：

  • 反馈循环：用户点赞 / 点踩 → 自动收集 bad case → 每周 prompt 迭代。
  • 版本迭代：Agent 的 prompt、工具、记忆都要版本化，变更可追溯、可回滚。
  • 用户教育：告诉用户 Agent 能做什么、不能做什么、怎么问能拿到好结果。降低预期差。
