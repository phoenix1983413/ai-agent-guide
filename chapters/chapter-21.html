第 21 章

构建你自己的第一个 Agent 产品

MVP 三层结构 / 冷启动 / 灰度发布 / 持续运营 / 30 天路线图

前 20 章讲的是「怎么造」，这一章讲「怎么落地你的第一个」。核心心法一句话：把 Agent 当产品运营，而不是当模型发布——模型只是零件，用户价值、反馈循环、灰度节奏才是生命线。

学习目标

  • 按「实验 → 试点 → 推广」三阶段推进，每阶段有过关门禁
  • 第一批工具与记忆按「高频 + 低风险 + 可度量」筛选
  • 用 30 天路线图把上线拆成可执行的动作

章节地图：21.1 MVP 结构 → 21.2 冷启动 → 21.3 灰度发布 → 21.4 持续运营 → 21.5 实验到生产路线图 → 本章产出。

21.1 从原型到 MVP：最小可用 Agent 的三层结构

MVP 不是「什么都做一点」，而是「只做最核心的一环，做到可靠」。Agent 产品的 MVP 三层：

  1. 感知层：一个输入通道（聊天框 / API / Webhook），不要一上来做全渠道。
  2. 大脑层：一个 LLM 调用 + 一个工具（搜索或数据库查询二选一）。
  3. 行动层：一个明确的输出（回复 / 文件 / 工单），且这个输出能被用户直接使用。

验证标准：3 个真实用户任务，成功率 > 80%。达标后再按「工具 → 记忆 → 多 Agent」的顺序逐层加。每加一层，回头看一次成功率是否被拖累——被拖累就停下来修，别急着堆功能。

21.2 冷启动：第一批工具和记忆怎么建

冷启动阶段没有用户数据，靠人工 bootstrap：

  • 工具：先做 3–5 个最高频工具，每个都有明确的成功 / 失败判定标准，宁缺毋滥。第一个工具建议选「读」而不是「写」——读错了好修，写错了要擦屁股。
  • 记忆：人工编写 20–50 条「常见问题 → 标准答案」，灌进知识库；同时准备 50 条评测用例（eval set），没有 eval set 就没有迭代依据。
  • 人设：写清 system prompt 的三件事——它是谁、能做什么、边界在哪（呼应第 20 章的透明性）。
  • 日志：从第一次调用就开始记全链路日志（第 10 章），后期所有评测和复盘都靠它。

21.3 灰度发布：小流量验证、回滚策略

Agent 的黑盒程度比传统软件高，灰度要更保守，采用「会话级灰度」——按 user_id 哈希分桶，同一个用户始终在同一档位，体验一致。放量节奏建议：

档位流量观察指标晋级条件
内部狗粮仅内部账号bad case 数、工具误调用率连续 3 天无高危 bad case
种子灰度5%任务成功率、人工接管率、单任务成本成功率 ≥ 80% 且成本达标
扩大灰度20%同上 + 用户满意度采样成功率稳定 ≥ 85%
全量100%全指标监控看板—

回滚的关键认知：Agent 出问题不是「降级」而是「关闭」——一键切回人工或旧系统，比给 Agent 打补丁更快更安全。

21.4 持续运营：反馈循环、版本迭代、用户教育

  • 反馈循环：点赞 / 点踩按钮只是入口，关键是 bad case 自动归档 → 归因（模型 / 工具 / 记忆 / prompt）→ 修复 → 回归 eval set。
  • 版本迭代：prompt、工具、记忆全部版本化（第 8 章），可灰度、可回滚、可对比 A/B。
  • 用户教育：告诉用户 Agent 能做什么、不能做什么、怎么提问效果更好。预期差是差评的第一来源。
  • 成本监控：单任务成本进 dashboard（第 14 章），异常账单比异常错误更早暴露问题。

21.5 从实验到生产：三阶段决策路线图

Agent 项目最常见的死法是「实验成功 → 直接推广 → 生产事故 → 全盘否定」。三阶段路线图的核心是每阶段只回答一个问题，答错了就停：

阶段唯一要回答的问题过关门禁典型时长
实验这件事 Agent 能不能做到 80 分？20 条核心 case 成功率 ≥ 阈值的 demo2–4 周
试点放进真实流程，用户真的会用吗？真实用户 + 周活率/接管率/满意度三项达标1–2 个月
推广规模化后成本、稳定性、合规撑得住吗？P95 成本达标 + 守护指标看板就绪 + 回滚演练通过持续

每条门禁配套一个「止损线」：实验连续两周无进展 → 换场景不换方法；试点周活率低于预期一半 → 回去重做需求判断（参考 Part 0 的「Agent 还是自动化」三问）。把「停」的规则提前写下来，是把研发负责人的判断力变成组织资产。

动手实验

  1. 把你现在的项目定位到 21.5 节三阶段之一，写下本阶段的唯一问题和当前门禁差距。
  2. 给每条门禁配上止损线和触发动作，拉团队对齐一次。
  3. 用 30 天路线图模板（下方）倒排你未来一个月的计划，标出每周的验证物。

本章产出：MVP 骨架 + 灰度控制器（双语言）

下面的代码把 MVP 三层和会话级灰度做成一个可直接扩展的骨架：含工具注册、单 LLM 循环、用户哈希分桶、按档位放量与一键关闭。

Python 版本

"""
MVP Agent 骨架 + 灰度控制器 —— Python
结构：感知层 stdin → 大脑层 LLM+工具 → 行动层回复；灰度按 user_id 哈希分桶。
"""
from __future__ import annotations
import hashlib, time
from dataclasses import dataclass, field

# ---------- 工具注册表（读优先） ----------
TOOLS: dict[str, callable] = {
    "search_docs": lambda q: f"[检索结果] {q} 相关文档摘要……",
    "query_order": lambda oid: {"order_id": oid, "status": "shipped"},
}

# ---------- 灰度控制 ----------
@dataclass
class Rollout:
    percent: int = 5                      # 当前灰度百分比
    enabled: bool = True                  # 一键开关
    killed_sessions: set[str] = field(default_factory=set)

    def in_rollout(self, user_id: str) -> bool:
        if not self.enabled or user_id in self.killed_sessions:
            return False
        bucket = int(hashlib.md5(user_id.encode()).hexdigest(), 16) % 100
        return bucket < self.percent     # 同一 user_id 恒定落桶 → 体验一致

rollout = Rollout(percent=20)

# ---------- MVP 大脑层：最小 ReAct 循环 ----------
def run_mvp(user_id: str, task: str, max_steps: int = 3) -> str:
    if not rollout.in_rollout(user_id):
        return "Agent 未对你开放（灰度中），已转人工 / 旧流程。"
    ctx = {"task": task, "steps": []}
    for step in range(max_steps):
        # 生产环境：此处调用 LLM 决定 think / act；演示用规则驱动。
        action, arg = _plan(ctx)
        if action == "finish":
            return arg
        if action.startswith("tool:"):
            tool = action[5:]
            result = TOOLS.get(tool, lambda a: "未知工具")(arg)
            ctx["steps"].append({"tool": tool, "arg": arg, "result": result})
        time.sleep(0.01)                   # 限速，避免演示刷屏
    return "（已达步数上限）请补充信息后再试。"

def _plan(ctx: dict) -> tuple[str, str]:
    """演示规划器：先检索再总结。生产中替换为 LLM 调用。"""
    if not ctx["steps"]:
        return "tool:search_docs", ctx["task"]
    return "finish", f"结论：基于 {len(ctx['steps'])} 步处理完成「{ctx['task']}」。"

if __name__ == "__main__":
    print(run_mvp("user-42", "怎么查询订单状态"))
    rollout.percent = 100                  # 晋级全量
    print(run_mvp("user-42", "再来一次"))
    rollout.enabled = False                # 一键回滚
    print(run_mvp("user-42", "又被关了"))

TypeScript 版本

/**
 * MVP Agent 骨架 + 灰度控制器 —— TypeScript
 */
import { createHash } from "node:crypto";

// ---------- 工具注册表 ----------
const TOOLS: Record<string, (a: string) => unknown> = {
  search_docs: (q) => `[检索结果] ${q} 相关文档摘要……`,
  query_order: (id) => ({ order_id: id, status: "shipped" }),
};

// ---------- 灰度控制 ----------
class Rollout {
  constructor(private percent = 5, private enabled = true,
              private killed = new Set<string>()) {}

  inRollout(userId: string): boolean {
    if (!this.enabled || this.killed.has(userId)) return false;
    const bucket =
      parseInt(createHash("md5").update(userId).digest("hex").slice(0, 8), 16) % 100;
    return bucket < this.percent;          // 同一 user_id 恒定落桶
  }

  setPercent(p: number) { this.percent = Math.max(0, Math.min(100, p)); }
  kill(userId: string) { this.killed.add(userId); }
  disable() { this.enabled = false; }
}

const rollout = new Rollout(20);

// ---------- MVP 大脑层 ----------
interface Step { tool: string; arg: string; result: unknown }

function runMvp(userId: string, task: string, maxSteps = 3): string {
  if (!rollout.inRollout(userId)) {
    return "Agent 未对你开放（灰度中），已转人工 / 旧流程。";
  }
  const steps: Step[] = [];
  for (let i = 0; i < maxSteps; i++) {
    const plan = decide(task, steps);            // 生产中替换为 LLM 调用
    if (plan.action === "finish") return plan.output;
    const fn = TOOLS[plan.tool];
    const result = fn ? fn(plan.arg) : "未知工具";
    steps.push({ tool: plan.tool!, arg: plan.arg, result });
  }
  return "（已达步数上限）请补充信息后再试。";
}

function decide(task: string, steps: Step[]):
  | { action: "finish"; output: string }
  | { action: "tool"; tool: string; arg: string } {
  if (steps.length === 0) return { action: "tool", tool: "search_docs", arg: task };
  return { action: "finish",
           output: `结论：基于 ${steps.length} 步处理完成「${task}」。` };
}

console.log(runMvp("user-42", "怎么查询订单状态"));
rollout.setPercent(100);                     // 晋级全量
console.log(runMvp("user-42", "再来一次"));
rollout.disable();                           // 一键回滚
console.log(runMvp("user-42", "又被关了"));

本章要点

  • MVP 三层只做最薄的一环，用「3 个真实任务成功率 > 80%」判定晋级。

  • 灰度按 user_id 哈希分桶，体验一致；回滚的定义是「关闭」不是「降级」。
  • 持续运营的核心循环：bad case 归档 → 归因 → 修复 → 回归 eval。
