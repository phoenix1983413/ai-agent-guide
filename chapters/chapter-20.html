第 20 章

Agent 伦理与对齐

价值对齐 / 透明性 / 责任归属 / 监管趋势 / 红线规则引擎

伦理听起来是哲学问题，落到工程上是一组可执行的规则和可回放的证据。本章把它拆成四块：对齐什么（价值）、告知什么（透明）、谁来负责（责任）、按什么法规办（监管），最后给一个可直接跑的红线规则引擎。

学习目标

  • 用风险分级框架判断你的 Agent 处于哪一监管档位
  • 把价值对齐、透明性、责任归属落到工程实践
  • 完成 EU AI Act 与中国合规要求的映射清单

章节地图：20.1 价值对齐 → 20.2 透明性 → 20.3 责任归属 → 20.4 监管趋势 → 20.5 风险分级与合规映射 → 本章产出。

20.1 价值对齐：什么是「正确的事」

Agent 的决策必须与人类价值观对齐，而价值观是多元的、语境依赖的、随时间演化的。工程上分三层落地，层与层之间是「硬 → 软」：

层内容例子实现方式
规则层不可协商的红线不生成违法内容、不替用户做不可逆决定代码硬校验，不可被 prompt 覆盖
偏好层用户个人偏好「回答要简洁」「先给结论再展开」User Profile 注入 system prompt
文化层地域 / 行业 / 组织规范金融场景话术合规、尊重当地习俗场景模板 + 领域知识库

关键原则：规则层必须在模型之外执行。把红线写进 prompt 只是「软约束」，模型可能被注入攻击绕过；把红线做成网关里的代码判断才是「硬约束」。

20.2 透明性：用户是否有知情权

用户有权知道自己在和 AI 交互，以及这个 AI 的能力边界与数据去向。透明性要求：

  • 身份披露：首轮对话明确告知「我是 AI 助手，不是人类客服」。法规在中国、欧盟都有对应要求。
  • 能力边界：告诉用户 Agent 能做什么、不能做什么、出错概率——尤其是高错误率的能力（如专业建议）要标注「仅供参考」。
  • 数据使用：告知哪些数据被记录、用于什么目的、保留多久、能否删除。
  • 来源标注：引用外部信息时给出出处链接，幻觉率高的场景必须强制。

20.3 责任归属：Agent 做错了，谁负责

法律上仍在演进，但工程上可以提前布局，让责任「可追溯、可干预、可界定」：

  • 可审计：完整决策链路留痕——用户输入、模型版本、system prompt 版本、每次工具调用的参数与结果，全部落到哈希链日志。
  • 可干预：运行中可随时暂停、接管、下钻到中间步骤；关键动作留人工确认点（第 11 章 danger_level）。
  • 可隔离：单个 Agent / 会话故障被限制在租户和会话边界内，不扩散到主系统，责任范围才能界定。
  • 可回滚：Agent 造成的外部副作用（发信、下单、发布）有补偿路径或人工撤回流程。

20.4 监管趋势：EU AI Act、中国算法推荐管理规定

全球 AI 监管收紧，自主 Agent 是重点对象：

法规核心要求对 Agent 的影响
EU AI Act风险分级监管，高风险系统需合规评估、风险管理、日志留存影响欧盟用户的 Agent 按高风险准备：全链路日志 + 人工监督点
中国算法推荐管理规定算法备案、用户知情、可关闭个性化、不得诱导沉迷面向国内 C 端需备案 + 提供「关闭个性化推荐」入口
中国生成式 AI 服务管理暂行办法内容安全、训练数据合规、安全评估面向公众提供生成式服务需过安全评估
ISO/IEEE Agent 安全标准自主系统安全与治理框架（制定中）跟踪即可，暂无强制力

务实建议：法规是底线不是上限。把日志、披露、人工确认三件事做扎实，无论规制如何演进都有解释空间。

20.5 风险分级与合规映射

EU AI Act 按风险把 AI 系统分四档，不同档位义务天差地别。先对号入座，再决定投入：

风险档位Agent 场景核心义务
不可接受社会评分、操纵性诱导、无差别抓取人脸禁止——没有合规路径
高风险招聘筛选、信贷评估、医疗辅助、教育测评风险管理体系 + 数据治理 + 技术文档 + 人工监督 + 日志留存
有限风险客服对话、内容生成告知用户「你在与 AI 交互」+ 生成内容标识
最小风险内部代码助手、垃圾邮件过滤无额外义务（仍建议自律）

国内的对照要点：生成式 AI 服务按《生成式人工智能服务管理暂行办法》做算法备案与安全评估；涉及算法推荐、深度合成的另有规定。工程侧最常用的五个动作：交互告知（明说我是 AI）+ 生成内容标识 + 训练数据来源说明 + 用户输入不用于训练的选项 + 日志留存。这五个都不难，难的是立项时就排进工期——事后补做的系统改造，成本是前置的十倍。

动手实验

  1. 用 20.5 节表格给你的 Agent 定档：不可接受 / 高 / 有限 / 最小，写下判断依据。
  2. 检查五个常用合规动作在你产品里的现状，缺的排期。
  3. 做一次「知情权演练」：随机问三个真实用户「你知道刚才和你对话的是 AI 吗」，答不上来说明告知没做到位。

本章产出：红线规则引擎（模型之外执行）

规则引擎放在 Agent 输出的下游：模型先跑，输出必须过规则引擎才送达用户。规则支持「命中的黑名单直接改写 + 降级话术」。

Python 版本

"""
红线规则引擎 —— Python
位置：模型输出 → [规则引擎] → 用户。红线判断在模型之外，prompt 注入绕不过。
"""
from __future__ import annotations
import re
from dataclasses import dataclass

@dataclass
class Rule:
    name: str
    pattern: str
    action: str = "fallback"        # fallback=整条替换 / mask=局部脱敏
    fallback_text: str = "这个话题我无法协助，我们聊点别的吧。"
    compiled: re.Pattern = None
    def __post_init__(self):
        self.compiled = re.compile(self.pattern, re.IGNORECASE)

RULES = [
    Rule("违法物品", r"(制造|购买|贩卖)\s*(炸弹|枪支|毒品)"),
    Rule("医疗诊断承诺", r"(确诊|治疗方案|吃这个药)", action="fallback",
         fallback_text="我不能提供医疗诊断，请咨询专业医生。"),
    Rule("投资保证收益", r"(保证|稳赚|保底).{0,4}(收益|盈利)", action="fallback",
         fallback_text="投资有风险，我不能做收益承诺，请理性决策。"),
    Rule("身份证明文", r"\d{17}[\dXx]", action="mask"),
]

class RedlineEngine:
    def __init__(self, rules: list[Rule]):
        self.rules = rules
        self.hits: list[str] = []        # 供审计与监控

    def filter(self, output: str) -> tuple[str, bool]:
        """返回 (安全文本, 是否触发过红线)。"""
        triggered = False
        for rule in self.rules:
            if rule.compiled.search(output):
                triggered = True
                self.hits.append(rule.name)
                if rule.action == "fallback":
                    return rule.fallback_text, True
                output = rule.compiled.sub("[已脱敏]", output)
        return output, triggered

# ---- 使用示例 ----
engine = RedlineEngine(RULES)
for text in [
    "根据描述，你确诊为二型糖尿病。",            # 触发医疗红线
    "身份证 110101199003077758 已记录。",                    # 触发脱敏
    "这个基金保证年化收益 20%。",                            # 触发投资红线
    "今天天气不错，适合出门散步。",                          # 正常放行
]:
    safe, hit = engine.filter(text)
    print(("BLOCKED " if hit else "PASS    ") + safe)
print("命中规则:", engine.hits)

TypeScript 版本

/**
 * 红线规则引擎 —— TypeScript
 */
type Action = "fallback" | "mask";

interface RuleSpec {
  name: string;
  pattern: RegExp;
  action?: Action;
  fallbackText?: string;
}

const RULES: RuleSpec[] = [
  { name: "违法物品", pattern: /(制造|购买|贩卖)\s*(炸弹|枪支|毒品)/i },
  { name: "医疗诊断承诺", pattern: /(确诊|治疗方案|吃这个药)/,
    fallbackText: "我不能提供医疗诊断，请咨询专业医生。" },
  { name: "投资保证收益", pattern: /(保证|稳赚|保底).{0,4}(收益|盈利)/,
    fallbackText: "投资有风险，我不能做收益承诺，请理性决策。" },
  { name: "身份证明文", pattern: /\d{17}[\dXx]/, action: "mask" },
];

export class RedlineEngine {
  private hits: string[] = [];

  filter(output: string): { text: string; triggered: boolean } {
    let triggered = false;
    let text = output;
    for (const rule of RULES) {
      if (!rule.pattern.test(text)) continue;
      triggered = true;
      this.hits.push(rule.name);
      if ((rule.action ?? "fallback") === "fallback") {
        return {
          text: rule.fallbackText ?? "这个话题我无法协助，我们聊点别的吧。",
          triggered: true,
        };
      }
      text = text.replace(rule.pattern, "[已脱敏]");
    }
    return { text, triggered };
  }

  hitSummary(): string[] {
    return [...this.hits];
  }
}

const engine = new RedlineEngine();
console.log(engine.filter("根据描述，你确诊为二型糖尿病。"));
console.log(engine.filter("今天天气不错，适合出门散步。"));
console.log("命中规则:", engine.hitSummary().join(", "));

本章要点

  • 对齐三层：规则（代码硬校验）/ 偏好（用户档案注入）/ 文化（场景模板），规则层必须在模型之外执行。
  • 透明三告知：身份是 AI、能力边界、数据去向——这既是伦理也是法规。
  • 责任三工程：可审计（哈希链日志）、可干预（人工确认点）、可隔离（租户与会话边界）。
  • 监管底线思维：日志、披露、人工确认做扎实，法规怎么演进都有解释空间。
