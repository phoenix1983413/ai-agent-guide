第 19 章

Agent 之间的协议与标准

A2A / MCP / 未来通用 Agent 接口

19.1 A2A（Agent-to-Agent）协议现状

A2A 是 Google 提出的 Agent 间通信协议，核心思想：把 Agent 看作一个「服务」，有标准接口（健康检查、任务提交、状态查询）。关键设计：

  • Agent Card：每个 Agent 发布一张「名片」，声明能力、端点、认证方式。
  • 任务生命周期：提交任务 → Agent 返回 task_id → 轮询 / 接收推送获取结果。
  • 流式响应：长任务支持 SSE 或 WebSocket 推送中间状态。

现状（2024–2025）：A2A 仍在快速迭代，协议细节尚未冻结，但方向已明确——用 REST + JSON Schema 做通用发现层，用 SSE 做事件流。

19.2 MCP（Model Context Protocol）详解

MCP 是 Anthropic 推出的开放协议，目标是统一「模型 ↔ 工具 ↔ 数据」的连接方式。三层架构：

  • Host：运行 MCP 的应用程序（IDE、聊天界面）。
  • Client：Host 内部的连接器，与 Server 保持 1:1 连接。
  • Server：提供工具（Tools）、资源（Resources）、提示词（Prompts）的服务。

MCP 的优势是「插拔式」：一个 Server 可以同时被多个 Host 使用，工具一次开发到处运行。目前生态增长快，但安全问题（Server 恶意行为）尚未完全解决。

19.3 未来的通用 Agent 接口长什么样

综合 A2A + MCP + 行业实践，未来通用接口可能呈现：

  • 发现层：Agent 注册中心，支持按能力搜索（如「能查订单的 Agent」）。
  • 协议层：统一消息格式（JSON + Schema），统一错误码，统一认证（OAuth 2.0 / mTLS）。
  • 运行时层：Agent 沙箱标准（启动 / 停止 / 资源限制 / 日志），类似容器时代的 Docker。
