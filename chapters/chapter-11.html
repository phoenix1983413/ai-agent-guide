第 11 章

安全、合规与治理

权限最小化 / 数据隐私 / 内容安全 / 合规上线

11.1 权限最小化：工具调用的能力边界

Agent 能做的事取决于它被授予的工具权限。权限最小化原则：

  • 每个工具只给完成功能所必需的最小权限。例如「发邮件」工具只能发预定义模板邮件，不能发任意内容。
  • 危险操作（删除、发送、支付）强制人工确认，Agent 只能「建议」不能「执行」。
  • 工具之间权限隔离：读取用户数据的工具不能同时调用外部 API 发送数据。

11.2 数据隐私：PII 过滤、记忆隔离、GDPR / 个保法

Agent 处理的对话可能包含身份证号、手机号、地址等 PII。必须：

  • PII 过滤：输入和输出都过一遍脱敏层，敏感字段替换为 `***`。
  • 记忆隔离：不同用户的记忆存在不同 namespace，禁止跨租户读取。
  • 删除权：用户要求删除时，能定位并删除该用户的所有记忆和日志。
  • 合规对齐：GDPR（欧盟）、个保法（中国）、HIPAA（医疗）等，根据业务属地选择适用法规。

11.3 内容安全：拒绝有害输出、审计不可抵赖

Agent 可能被诱导生成有害内容，或被利用发起攻击。防线：

  1. 输入层：敏感词过滤 + 意图识别。
  2. 模型层：使用带安全对齐的模型（如 GPT-4o、Claude 3），并设置 system prompt 约束。
  3. 输出层：分类器二次审核，高风险内容拦截。
  4. 审计层：所有工具调用和敏感输出留痕，不可删除、不可篡改。

11.4 合规上线：企业内部审批流程

Agent 不是普通功能，上线前必须过安全评审。建议流程：

  • 内部测试：研发团队内部使用 1–2 周，收集问题。
  • 安全评审：安全团队审查工具权限、数据流、PII 处理、审计日志。
  • 灰度发布：先开放给 5% 用户，监控错误率和异常行为。
  • 用户告知：明确告知用户在与 AI 交互，哪些数据会被记录。
  • 回滚预案：出问题能一键关闭 Agent 功能，不影响主系统。

本章产出：Agent 上线检查清单

以下清单可以直接作为上线前的 Gate Check：

  • □ 所有工具权限已最小化，危险操作有人工确认
  • □ PII 过滤层已覆盖输入和输出
  • □ 用户记忆已按 namespace 隔离
  • □ 审计日志已落地且不可篡改
  • □ 红队测试已完成，无高危漏洞
  • □ 回滚预案已演练
  • □ 用户告知文案已上线
